# Day 53 : Constrained-random verification of the ALU

## Why random test
To test all the input pairs for one ALU operation we would have 2^32 combinations for both inputs of ALU. To test every combination is exhaustive and handpicking few input pairs do not test the working correctly and may miss some of the cases.

## Constrained Random
If the input pairs are pure random then the probability of some of the cases occuring will be very very low and may not be encountered inside fix set of random pairs. So we added a variable "roll" which can have values from 1 to 10 and upon getting 1, the value of input "a" is directly copied to input "b" so that the case of "a==b" is tested about 1 time in 10 iterations.

## Generator Rules
The numbers are always randomly generated within 0 to 2**32-1. Whether to take the number as is or the signed interpretation is upto the reference model (SLT, SRA) not the generator.

## Seed
cocotb seeds random from the clock. After running the make command we can see what was the seed used for that test and we can reproduce the same random values again using that seed using this command before running make. <br> In PowerShell, this is done via: <br>
[ $env:COCOTB_RANDOM_SEED = SEED_NUMBER ]
