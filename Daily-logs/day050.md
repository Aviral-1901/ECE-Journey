## SUB reference model
Using expected_result=(a-b) % (2**32) means the value stays within the range of 32 bit mimicking hardware behaviour. Python's negative results don't match directly the hardware wrap around so we use the modulo operator method to make it work and matche hardware's 2's complement wraparound.

## Signed Conversion
The maximum unsigned value without having MSB=1 for 32bits is 2,147,483,648 which acts as the threshold for determining the number as positive or negative. So what we do is if the number is greater or equal to that threshold then we get signed_value = value - max_size(4,294,967,296). So the number greater than threshold is actually a negative number and less than those are positive numbers in case of signed number.
